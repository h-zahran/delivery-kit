# Contract: the static shell analysis job

What the new continuous-integration job guarantees. Each clause names how
it is verified.

---

## S1 — The job runs on every pull request and every push to the default branch

It shares the workflow's existing triggers. It is a job beside the test
matrix, not a step inside it, so a red analysis is distinguishable from a
red test at a glance.

**Verifiable by:** the job appearing in a run of each kind.

---

## S2 — The analysed set is discovered, never listed

The set is produced by asking the repository for its tracked files
matching the shell extensions, with the vendored scaffold directory
excluded by pathspec. No filename is written into the job.

**Verifiable by:** adding a shell file at a new tracked path outside the
exclusions and observing the job analyse it with no file edited to admit
it.

---

## S3 — An empty set is a failure

If the discovery yields nothing, the job fails with a message naming that
condition. A scan that read nothing and a scan that found nothing do not
report the same result.

**Verifiable by:** widening the exclusion until the discovery is empty and
observing the named failure.

---

## S4 — The boundary carries its reason

The job states, where a reader of it will find them, what is analysed,
what is excluded, and why each exclusion exists. The vendored scaffold's
reason is that it is not authored here and is regenerated by re-running
its upstream tool. The test suites' reason is that the analyser reports
dozens of findings on them of which most are deliberate constructs, and
that bringing them in is separate work.

**Verifiable by:** reading the job.

---

## S5 — Any finding fails the run

The job fails when the analyser reports anything on a file within scope,
and fails when the analyser cannot execute. It never passes over an
unanalysed tree.

**Verifiable by:** planting one real defect in a file within scope and
observing the job go red; then removing it and observing green. Both
directions, each with the planted line echoed before the verdict is
believed.

---

## S6 — Every suppression carries a reason

A suppression sits at the line it silences, in the file that owns it, and
states why. There is no job-level suppression list.

**Verifiable by:** reading every suppression in the tree and finding a
reason beside each.

---

## S7 — The analyser identifies itself

Every run prints the analyser's version, so a red that arrives on
unchanged code is diagnosable in one look.

**Verifiable by:** the version appearing in the job log.

---

## S8 — The job analyses the code this feature adds

The shared version-agreement script is discovered and analysed by S2's
rule, with nothing added to admit it. This is the first proof the rule
works.

**Verifiable by:** the script appearing in the analysed set.

---

## S9 — A path containing a space survives

The set is carried from the producing command to the consuming command in
a form that does not split a path on whitespace.

**Verifiable by:** adding a tracked shell file whose path contains a
space in a scratch tree and observing it analysed as one file.
